# Бюджет — планировщик личного и семейного бюджета (Android)

Офлайн-приложение: планируете регулярные доходы и расходы, а оно по календарю считает,
сколько денег останется свободными — в месяц и в неделю. Валюта — сум (UZS).

**Стек:** Kotlin · Jetpack Compose · Material 3 · Room · Navigation Compose · MVVM · Kotlin Flow.
Без интернета, без регистрации, данные только на устройстве.

---

## Как собрать приложение и APK

### Вариант 1 — Android Studio (проще всего)
1. Установите **Android Studio** (Koala 2024.1 или новее). Внутри уже есть JDK 17+.
2. `File → Open` → выберите папку `BudgetPlanner`.
3. Дождитесь окончания Gradle Sync (при первой синхронизации нужен интернет — скачаются зависимости).
   Если студия предложит установить Android SDK Platform 34 — согласитесь.
4. Запуск на телефоне/эмуляторе: кнопка **Run ▶**.
5. Файл APK: `Build → Build Bundle(s) / APK(s) → Build APK(s)`.
   Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

### Вариант 2 — командная строка
Нужны JDK 17+ и Android SDK (переменная `ANDROID_HOME` или файл `local.properties` со строкой
`sdk.dir=/путь/к/Android/Sdk`).

```bash
./gradlew assembleDebug          # Windows: gradlew.bat assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

`./gradlew assembleRelease` тоже даёт устанавливаемый APK (`app/build/outputs/apk/release/app-release.apk`),
но он подписан **debug-ключом** — для личного использования подходит, для публикации в магазине нужен свой ключ.

### Установка APK на телефон
Скопируйте `app-debug.apk` на телефон и откройте его (разрешите установку из неизвестных источников),
либо подключите телефон по USB с включённой отладкой и выполните `adb install app-debug.apk`.

## Тесты

```bash
./gradlew :domain:test
```

Тесты покрывают бизнес-логику (модуль `:domain`, чистый Kotlin, без Android):

- календарь: месяцы на 28/29/30/31 день, 4 или 5 одинаковых дней недели, день 31 в коротких месяцах,
  «последний день месяца», ежегодные операции (29 февраля), единоразовые, ежедневные, даты начала/окончания;
- бюджет: несколько доходов, отсутствие доходов, расходы больше доходов, нулевой и отрицательный остаток,
  обязательные и необязательные расходы, «свободно в неделю» для текущего, будущего и прошлого месяца;
- факт и план: фактический расход внутри плана, сверх плана, в категории без плана;
- изменение, отключение и удаление регулярного расхода; сценарий «что если»;
- форматирование сумм.

## Как устроен расчёт

**Точный календарь.** Плановая операция превращается в реальные даты месяца
(`RecurrenceCalculator`): еженедельный расход по субботам — это 4 или 5 платежей в зависимости от месяца,
а не «×4». Число, которого нет в месяце (31 февраля), сдвигается на последний день.

**Прогноз месяца** = доходы − расходы. Свободно в неделю = свободные деньги ÷ оставшиеся недели
(остаток месяца в днях ÷ 7, но не меньше одной недели).

**Модель «конвертов» для плана и факта.** План по категории — это лимит на месяц.
- Фактическая трата внутри лимита прогноз не меняет: эти деньги уже были запланированы.
- Трата сверх лимита и траты в категориях без плана увеличивают прогноз расходов.
- Итог по категории = max(план, факт). Поэтому плановая и фактическая зарплата не считаются дважды.

Так «Свободно» остаётся честным прогнозом, а факт виден отдельно («Уже потрачено…», «Осталось в плане»).

**График баланса** показывает накопленное изменение остатка с начала месяца (без начального остатка
на счёте), с отметкой самой низкой точки.

## Архитектура

```
domain/   (чистый Kotlin, тестируется без Android)
  model/       Category, PlanItem, Transaction, настройки
  calc/        RecurrenceCalculator, BudgetCalculator, ScenarioSimulator, MoneyFormat
  repository/  интерфейсы репозиториев
  usecase/     сценарии использования
  demo/        демо-данные
app/
  data/          Room (сущности, DAO, база), DataStore (настройки), реализации репозиториев
  presentation/  ViewModel + UiState
  ui/            Compose: theme, components, charts, home, plan, operations, settings, onboarding
```

Данные проходят путь `Room → Repository → UseCase → ViewModel (StateFlow) → Compose`. Экран не считает деньги сам —
вся математика в `domain`.

## Экраны
- **Главная** — свободные деньги, «≈ в неделю», доходы/расходы, обязательные и необязательные расходы,
  сравнение доходов/расходов/остатка, кольцевая диаграмма по категориям (тап по категории — детали), баланс по дням.
- **План** — регулярные доходы и расходы; свайп влево — удалить (с подтверждением), тап — изменить.
  В форме виден эффект: «свободно было → станет».
- **Операции** — фактические операции по дням.
- **Настройки** — тема, первый день недели, свои категории, демо-данные, удаление данных.
- Кнопка **«+»**: вводите сумму → нажимаете категорию → операция сохранена.
- **Онбординг** из трёх шагов; «Пропустить» есть на каждом.

## Демо-данные
`Настройки → Загрузить демо-данные` добавляет пример: зарплата 40 000 000, подработка, жильё, кредит,
еженедельные продукты по субботам, коммуналка в последний день месяца и несколько фактических трат.

## Отклонения от исходного ТЗ (осознанные)
- Вместо двух сущностей `RecurringIncome`/`RecurringExpense` одна таблица `plan_items` с полем `type`:
  меньше дублирования, одинаковая логика расписания.
- В `Category` добавлено поле `isEssentialDefault` — подсказка «обязательный ли расход» для новых операций.
- Настройки хранятся в DataStore, а не в таблице Room.
- Графики нарисованы на Canvas без сторонних библиотек: меньше зависимостей и риска несовместимости версий.
- DI — вручную (`AppContainer`), без Hilt: проще собирать и читать; легко заменить на Hilt/Koin.
- Суммы — целые числа (`Long`). Для валют с копейками потребуется хранить минорные единицы.
- Кнопка «+» открывает шторку быстрого добавления с переключателем «Расход / Доход» вместо отдельного выбора —
  на одно нажатие меньше.

## Сборка APK на GitHub (без Android Studio)
1. Создайте пустой репозиторий на github.com и загрузите в него **содержимое** папки проекта
   (включая скрытую папку `.github`).
2. Откройте вкладку **Actions** — сборка стартует сама после загрузки (или запустите вручную: *Build APK → Run workflow*).
3. Когда появится зелёная галочка, откройте запуск и внизу, в разделе **Artifacts**,
   скачайте `budget-planner-debug-apk` (внутри `app-debug.apk`).
4. Если сборка красная, откройте шаг с ошибкой и пришлите его последние строки.
